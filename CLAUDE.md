# quakesettings

Astro 4 static site for Quake Live player settings. Deployed by GitHub Pages
from `main` (site https://stripyq.github.io/quakesettings, base `/quakesettings`).

## Layout
- `src/content/players/*.yaml` — one file per player; Zod schema in `src/content/config.ts`.
- `src/content/{mice,mousepads,keyboards,monitors,headsets}/` — hardware, referenced by filename slug.
- `public/data/hoq/<steamId>/history.json` — rating history, append-only.
- `public/data/player-registry.json` and `src/data/player-registry.json` — generated by `scripts/generate-form-data.js`.
- `scripts/` — data maintenance; see rules below.
- `scripts/_legacy/` — retired scripts kept for reference only. Nothing in there is ever run.
- Stylesheet: public/styles/global.css is the only global stylesheet and is served as-is. Do not create a src/styles copy.

## Rating field ownership
- `hoqCtfRating`, `hoqCtfGames`, `hoqTdmRating`, `hoqTdmGames` are written ONLY by `scripts/fetch-hoq-ratings.cjs`
  (source: http://stats.houseofquake.com/export_rating/{ctf,tdm}.json).
- `ctfRating`, `tdmRating`, `ctfGames`, `tdmGames`, `*RatingUpdated` are written ONLY by `scripts/sync-hoq-to-display.cjs`.
- `qllrCtfRating`, `qllrCtfGames` are written ONLY by `scripts/fetch-qllr-ratings.cjs`.
- Never edit rating fields by hand except to delete a stale value.

## Scripts: hard rules
- `scripts/_legacy/` holds `update-hoq-ratings.cjs`, `fetch-ratings.cjs`, `patch-hoq-from-json.cjs`,
  `fetch-qlrace.js` and `migrate-players.cjs`. They are destructive (they rewrite rating fields from stale
  CSVs, hardcoded values or a dead server, or re-dump whole YAML files). NEVER execute them from there and
  NEVER move them back into `scripts/`. `npm run fetch:hoq-ratings` runs `scripts/fetch-hoq-ratings.cjs`.
- `scripts/_legacy/` also holds the dead-server fetchers `build-hoq-archive.cjs`, `fetch-season-stats.cjs`,
  `build-alltime-h2h.cjs`, `fetch-hoq-maps.cjs`, `fetch-hoq-stats.cjs`, `fetch-hoq-activity.cjs`,
  `fetch-activity-data.cjs`, `fetch-player-activity.cjs` and `sync-hoq-games.cjs`. Never run them either.
- NEVER run two YAML-writing scripts at the same time. Each one reads, edits and writes whole files; the slower one overwrites the other. Run strictly in sequence.
- Run refresh steps one at a time in the terminal. Never paste a block that ends in git push; the push runs even if the build failed.
- The HoQ server 88.214.20.58 and the season API 77.90.2.137 are both dead. https://hoqstats.vercel.app is the
  match source; `scripts/lib/hoqstats.cjs` is the only place that talks to it.
- Refresh order, each a separate script run: `fetch-hoq-ratings.cjs` → `append-hoq-history.cjs` (reads the
  hoq* fields the fetch just wrote; it is not called from inside the fetch) → `sync-hoq-to-display.cjs` →
  `fetch-qllr-ratings.cjs` → `generate-form-data.js` → `sync-hoqstats-archive.cjs` →
  `derive-archive.cjs --gt=ctf,tdm` → `derive-tdm-all.cjs` → `derive-activity-ctf.cjs` → `derive-player-activity.cjs` →
  `derive-signatures.cjs --gt=ctf,tdm` → `derive-rating-stories.cjs --gt=ctf,tdm` → `derive-season-stats.cjs` →
  `derive-map-ratings.cjs` → `derive-alltime-h2h.cjs`. Everything from `sync-hoqstats-archive.cjs` on writes no YAML. Its download cache
  `data-archive/hoqstats-cache/` is gitignored. Commit after verifying `git diff --stat` touches only expected fields.
- `public/data/archive/<gt>.jsonl`: older lines end in CRLF, newer ones in LF. Never rewrite the file wholesale
  (no read-all/write-all, no line-ending normalization); only append, or use `sync-hoqstats-archive.cjs`, which
  keeps existing bytes. Player rows may end in an optional `mr` ([mu, sigma, delta, games], the per-map TrueSkill after
  that match); `sync-hoqstats-archive.cjs --update-existing --fields mr` adds it to existing lines and changes no other byte.
- `public/data/hoq/<steamId>/map_ratings.json` is generated by `derive-map-ratings.cjs` and
  `public/data/player-activity/<steamId>.json` by `derive-player-activity.cjs`, both from the archive; never edit them by hand.
- Activity charts hide the current, incomplete month or week at render time (`src/utils/completePeriods.ts`); derived
  activity files always hold every period, the current one included.
- After any refresh, grep for dropped keys: a script that strips and re-adds fields can delete a field when the upstream value is missing.
- `yaml-safe-write.cjs` only detects dropped top-level keys; it does not catch blanked values or damage inside `qlrace:`.

## Data conventions
- Dates are strings: quote `lastUpdated` and every `*Updated` field in YAML (`"2026-10-16"`). Unquoted dates become Date objects and render as garbage.
- `lastUpdated` is stored as YYYY-MM-DD and displayed truncated to YYYY-MM.
- `steamId` is a quoted 17-digit string; omit the field rather than writing `""`.
- `published: false` means ratings-only; such players must not be linked from any page.
- Rating 0 or negative is a valid TrueSkill value; use `== null` checks, never `||` or truthiness.
- Hardware fields must match a filename in the corresponding `src/content/<type>/` directory.
- Map keys: lowercase, no spaces, no `ctf_`/`tdm_` prefix (`normalizeMapKey` in `scripts/lib/hoqstats.cjs`; the compare
  and player pages inline the same rule).

## Privacy
- The site owner is anonymous. Never commit real names, local paths containing a username, personal email addresses, or paths to personal note folders. Use `os.homedir()` or env vars in scripts.
- Commit with the GitHub noreply address.
- Never add `realName` or other personal data for players.

## Build
- `npm run build` runs `prebuild` (generate-form-data + sync-hoq-to-display), which mutates repo files. Use `npx astro build` for a build-only check.
- No tests. Verify with `npx astro build` and a `git diff --stat` review.
